# HLAS Master Data 표준

문서 버전: v1.0  
대상: 주문공급집계표 운용본 / `기초` 시트  
기준일: 2026-07-29

## 1. 표준화 원칙

- 기존 `기초` 시트의 A:G 구조와 기존 수식을 변경하지 않는다.
- 물품코드를 Master Data의 기본 식별자로 사용한다.
- 물품코드는 표시 형식을 포함한 문자열로 취급한다.
- 기존 물리 컬럼은 유지하고, 확장 항목은 논리 필드로 먼저 정의한다.
- 검증은 읽기 전용으로 수행하며 자동 수정하지 않는다.
- 신규 기능은 물리적 열 번호가 아니라 헤더명을 기준으로 참조한다.

## 2. 현행 Master Data 구조

| 논리 필드 | 현행 컬럼 | 필수 | 형식 | 기준 |
|---|---|---:|---|---|
| ITEM_CODE | 물품코드 | Y | 문자열 | 고유, 공백 금지 |
| ITEM_NAME | 물품명 | Y | 문자열 | 공백 금지 |
| PRICE | 금액 | N | 0 이상 숫자 | 현행 결과 유지 |
| TEMPERATURE_TYPE | 저장상태 | Y | 코드 | 상온/냉장(가공)/냉장/냉동/빵/기타 |
| STORAGE_PICK_KEY | 저장상태+집품순서 | Y | 파생 문자열 | 저장상태 + 숫자 집품순서 |
| PRODUCER_OR_LOGISTICS_SOURCE | 물류지 | Y | 문자열 | 현행 생산·물류 출처 |
| PICKING_ORDER | 집품순서 | Y | 양수 | 저장상태 내 정렬 기준 |

## 3. 확장 논리 필드

아래 항목은 현재 `기초` 시트의 독립 컬럼이 아니다. 기존 수식 영향 분석과 데이터 이관 계획 승인 전에는 물리 컬럼을 추가하지 않는다.

| 논리 필드 | 권장 컬럼명 | 현재 처리 | 확장 기준 |
|---|---|---|---|
| PRODUCER | 생산자 | 물류지와 분리되지 않음 | 생산자 Master 도입 시 코드 참조 |
| COURSE | 코스 | 주문내역 배송코드 및 31~36코스 시트 | 코스 Master 도입 시 배송코드와 매핑 |
| SUPPLY_TYPE | 공급구분 | 별도 독립 컬럼 없음 | 주문/매장 공급 규칙 승인 후 도입 |
| ACTIVE_YN | 사용여부 | 물품명에 중지/불가 표기가 혼재 | Y/N 코드 도입 전 기존 품목 필터 영향 검증 |

## 4. 참조 관계

| 업무 | 물리 시트/영역 | Master 참조 | 기준 |
|---|---|---|---|
| 주문내역 | 주문내역 | 물품코드, 물품명, 저장상태, 집품순서 | 물품코드로 기초 참조 |
| 주문공급 | 총수량, 31~36코스 | 물품코드, 저장상태, 집품순서, 코스 | 기초 A:G 및 배송코드 사용 |
| 매장공급 | 별도 운용본 | 물품코드, 저장상태, 공급구분 | 후속 통합 점검 대상 |
| 집품 | 총수량, 코스 시트 | 저장상태+집품순서, 집품순서 | 정렬과 출력 순서 결정 |
| 검수 | 검증관리 | 물품코드, 물품명, 저장상태 | 누락 및 불일치 확인 |
| 출고 | 코스 시트 | 배송코드, 코스, 물품코드 | 코스별 출고자료 구성 |

## 5. Validation 규칙

### 오류(ERROR)

- 필수 헤더 또는 필수값 누락
- 중복 물품코드
- 중복 저장상태+집품순서
- 허용되지 않은 저장상태
- 0 이하 또는 숫자가 아닌 집품순서
- 주문내역 물품코드가 기초시트에 없음

### 경고(WARNING)

- 주문내역의 물품명 또는 저장상태가 기초시트 값과 다름

### 정보(INFO)

- 현재 주문내역에 참조되지 않은 Master 물품 수
- 독립 컬럼이 아직 없는 확장 논리 필드

## 7. 향후 확장 기준

1. 생산자·코스·공급구분·사용여부는 코드 Master로 분리한다.
2. 기존 `기초` A:G를 즉시 변경하지 않고 호환 View 또는 매핑 계층을 먼저 둔다.
3. 신규 필드 도입 전 주문공급·매장공급·집품·검수·출고의 회귀 테스트를 완료한다.
4. 운영 데이터 자동 정정은 별도 승인 TASK로 분리한다.
5. 모든 신규 기능은 `MasterDataService`의 표준 논리 필드를 사용한다.
